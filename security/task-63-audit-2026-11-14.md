# Task 63 security and data-handling audit

Audit date: November 14, 2026

## Scope and commands

The audit covered committed-secret detection, synchronized Python dependencies,
deployed frontend dependencies, administrator authorization, CMS source-fetch
restrictions, public/private serialization boundaries, and browser output
encoding.

```sh
make security-check
cd backend && uv run pip-audit --local --skip-editable --progress-spinner off
cd frontend && npm audit --omit=dev --audit-level=moderate
cd frontend && npm audit --json
make check
```

The dependency scans query current external advisory services and therefore
require network access. The recorded tools were uv 0.11.32, pip-audit 2.10.1,
and npm 11.6.2. CI uses the repository's Node 22 selection rather than the local
unsupported Node 23 shell used for the manual npm scan.

## Findings and remediation

### Production dependencies

- The first npm production scan reported one moderate transitive `seroval`
  finding. The lockfile moved `seroval` from 1.6.9 to 1.8.1 and
  `seroval-plugins` from 1.6.9 to 1.8.0 within existing parent constraints. The
  repeated production scan reported zero known vulnerabilities.
- The first Python scan reported known vulnerabilities in `pypdf` 6.21.2,
  `certifi` 2026.7.22, and `opentelemetry-api` 1.45.1. The lockfile moved them to
  6.21.4, 2026.10.23, and 1.45.2 respectively without widening application
  dependency ranges. The repeated Python scan reported zero known
  vulnerabilities.
- `pip-audit` skips the editable local application package itself because it is
  not a third-party release. Application code is covered by tests, Ruff, and
  CodeQL instead.

### Development-only advisories

The full npm audit also reported seven moderate entries in the lint-only
`typescript-eslint` dependency chain, rooted in a `minimatch` denial-of-service
advisory. These packages are not bundled into the Vite production output. At
audit time npm proposed a contradictory downgrade to a version that its own
reported affected range still included, so no unsafe automated or forced change
was applied. Dependabot remains responsible for presenting a valid patched
toolchain update when one is available. The CI blocking audit intentionally
targets deployed dependencies and fails on moderate-or-higher findings.

## Boundary verification

- Protected `/api/admin/...` data and mutations require a valid signed session;
  unauthenticated requests fail server-side.
- Public measure, comparison, impact, activity, CSV, and Excel projections use
  explicit response fields and exclude pending candidates, private notes,
  review events, and unpublished drafts.
- Source registration accepts only HTTPS `cms.gov` hosts or subdomains, rejects
  user information, IP literals, fragments, and non-default ports, and
  revalidates every redirect. Downloads have redirect, timeout, content-kind,
  and byte-size limits, while failures are audited without creating a revision.
- React renders API-provided text through ordinary text nodes. An integration
  test supplies an image/event-handler payload and verifies that it remains
  visible text, creates no image element, and executes no handler.
- CSV and Excel exports neutralize formula-like cells and contain only
  allowlisted public comparison fields and official evidence links.

## No-PHI and AI data-use policy

This application stores public CMS program and measure material, source
provenance, reviewer workflow metadata, and administrator-authored notes. It
must not receive or store patient-level records, beneficiary identifiers, EHR
data, claims, or any other PHI.

Optional AI calls may receive only the minimum approved or private CMS source
excerpts, structured measure metadata, and constrained instructions needed for
the requested proposal. Credentials, session cookies, environment values,
private reviewer notes, and any patient-level data must never be sent to an AI
provider. AI outputs remain private proposals until a human reviews them, and
AI cannot verify evidence, approve a record, or publish public content.

## Residual operational requirements

- Set `CMSQI_ADMIN_SESSION_SECURE=true` behind production HTTPS and use unique,
  non-default administrator credentials and session secrets.
- Review CodeQL and Dependabot results for the exact deployed commit.
- Rerun `make security-audit` before a release because advisory data changes
  independently of source code.
- Rotate and remove any secret that appears in a log, screenshot, diff, issue,
  or conversation, even if the repository scanner did not detect it.
